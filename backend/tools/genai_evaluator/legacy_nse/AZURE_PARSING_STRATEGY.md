# Azure Parsing Strategy: The "Golden Cache" Architecture

> **Objective**: Extract maximum semantic value from Azure Document Intelligence (Layout Model) while minimizing costs via a "Parse Once, Enrich Offline" strategy.

---

## 1. The Core Philosophy: "Golden Cache"
We treat the `AnalyzeResult` JSON from Azure as the **Source of Truth**.
*   **Step 1**: Call Azure API `prebuilt-layout` with **ALL** features enabled (`styles`, `figures`).
*   **Step 2**: Save raw JSON to disk (`.cache/azure_results/<hash>.json`).
*   **Step 3**: All downstream tasks (Chunking, Metadata, QA) consume this JSON, *not* the PDF.

---

## 2. Feature Utilization Map

| Azure Feature | Element Object | RAG Usage | Implementation Phase |
| :--- | :--- | :--- | :--- |
| **Paragraphs** | `paragraphs` | **Semantic Chunking**. Text is grouped by natural reading order. | **Phase 1 (Done)** |
| **Roles** | `paragraphs[i].role` | **Section Detection**. Identify `title`, `sectionHeading`, `pageHeader` to preserve hierarchy. | **Phase 4 (Next)** |
| **Tables** | `tables` | **Structured Data**. Handle `rowSpan`/`colSpan` to "fill" cells for LLM context. | **Phase 1 (Done)** |
| **Figures** | `figures` | **Chart Extraction**. Crop images of "Revenue Growth" charts for Vision LLM analysis. | **Phase 5 (Future)** |
| **Styles** | `styles` | **Emphasis Detection**. `isHandwritten` or `font_weight` (via feature flag) to detect "Focus Areas". | **Phase 4** |
| **Sections** | `sections` | **Hierarchy**. Recursive tree of `elements` (Parent Section -> Child Section). | **Phase 4** |

## 3. Semantic Synthesis Strategy

We do not just "split by max_tokens". We "reconstruct" the document logic.

### 3.1 The "Section-Aware" Chunking Algorithm
Instead of blindly splitting text, we iterate through the `paragraphs` list:

1.  **Scan Loop**: Walk through `result.paragraphs`.
2.  **Break on Role**: If `role == 'sectionHeading'` or `role == 'title'`:
    *   **Close current chunk**.
    *   **Start new chunk** with this Header as the "Context Label".
3.  **Merge Content**: Accumulate standard text paragraphs.
4.  **Inject Tables**: If a Table falls between paragraphs, insert its `markdown` representation immediately.

**Result**: Chunks are naturally bounded by the document's own structure (e.g., "Management Discussion" vs "Financial Results").

### 3.2 Metadata Enrichment (Offline)
Using the Golden Cache, we run cheap local passes:
*   **Headers**: Use `pageHeader` role to strip repetitive noise (e.g., "Q3 FY25 Earnings Call" on every page) from the core content, but keep it as metadata.
*   **Footers**: Use `pageFooter` to ignore page numbers / disclaimers in the semantic embedding.

## 4. Specific Implementation Logic (Python)

### A. Constructing the Context
When converting a Paragraph to a Chunk, we look at the `sections` hierarchy.
*   **Input**: `paragraph` at index `15`.
*   **Lookup**: Find which `section` contains `/paragraphs/15`.
*   **Action**: Prepend the Section Title to the text.
    *   *Original*: "Revenue grew 10%."
    *   *Enriched*: "**[Section: Financial Highlights]** Revenue grew 10%."

### B. Table "Cell Filling"
(Already Implemented in `AzureParsingStrategy`)
*   **Problem**: Merged Header "FY25" spans 4 columns.
*   **Action**: Repeat "FY25" in valid JSON/Markdown for all 4 sub-columns.

### C. Figure Handling
*   **Detect**: `result.figures` list.
*   **Action**: 
    1.  Crop image using `bounding_regions`.
    2.  Check `caption` property.
    3.  Create a `ImageNode` with the caption + image summary (generated by GPT-4o-mini).

## 5. Cost Control
*   **Rule 1**: Never call `begin_analyze_document` without checking `hash(pdf)` first.
*   **Rule 2**: Enable `features=[DocumentAnalysisFeature.STYLE_FONT]` and `output=[AnalyzeOutputOption.FIGURES]` in the *first* call to avoid re-running just to get fonts later.
