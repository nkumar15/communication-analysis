# RAG Experimentation & Lifecycle Strategy

## 1. The Challenge
RAG systems are not "set and forget". They require continuous evolution to address:
- **Model Drift**: New, better embedding models released (e.g., OpenAI v3 large, Cohere v3).
- **Data Drift**: Changing document structures (e.g., Annual Reports changing layout).
- **Quality Stagnation**: Reaching a plateau in retrieval accuracy (Recall@K).

## 2. Re-Embedding Strategy
*When and how to regenerate vector embeddings.*

### Triggers
1.  **Parser Upgrade**: Switching from `pdfplumber` to LlamaParse (improves text quality = needs new embeddings).
2.  **Model Upgrade**: Switching embedding provider (e.g., OpenAI -> Fine-tuned GTE-Large).
3.  **Chunking Strategy Change**: Changing chunk size (512 -> 256 tokens) or overlap.

### Implementation: "Blue-Green" Indexing
To avoid downtime during re-embedding:
1.  **Versioned Indices**: Create `rag_nse_v2` (new config) alongside `rag_nse_v1` (live).
2.  **Backfill**: Run a background worker job to re-process documents from MinIO -> New Index.
3.  **Validation**: Run the **Golden Dataset** evaluation against `v2`.
    4.  **Switchover**: If `v2` metrics > `v1`, update the alias `rag_nse` to point to `rag_nse_v2`.
5.  **Deprecate**: Delete `v1` after 24h stability.

## 3. Experimentation Framework
*Systematic approach to improving metrics.*

### Variables to Tune
- **Ingestion**: Chunk Size (256, 512, 1024), Chunk Overlap (10%, 20%), Parser (Layout-aware vs Text).
- **Retrieval**: Top-K (5, 10, 20), Hybrid Weight (Alpha 0.5 vs 0.7), Reranker (Cross-Encoder vs ColBERT).

### Tracking (Experiment Log)
Maintain a structured log (JSON/Markdown) of runs:
```json
{
  "experiment_id": "EXP-004",
  "date": "2025-12-27",
  "config": { "chunk_size": 256, "retrieval_mode": "hybrid", "reranker": "ms-marco" },
  "results": { "faithfulness": 0.92, "context_recall": 0.88, "latency_ms": 450 }
}
```

## 4. Golden Dataset Strategy
*The source of truth for evaluation.*

### Composition
1.  **Synthetic (80%)**: Generated by LLM (GPT-4) from chunks. Good for volume.
    - *Prompt*: "Given this context about HDFC Revenue, generate a hard question and the answer."
2.  **Human Verified (20%)**: "Gold Standard" questions derived from real user logs or Domain Experts.
3.  **Hard Negatives**: Questions that *look* relevant but have no answer in the knowledge base (e.g., "What is HDFC's stock price prediction for 2030?"). System must reply "I don't know".

### Lifecycle
1.  **Bootstrap**: Use `deepeval` or `ragas` to generate initial 50 pairs from the pilot docs.
2.  **Evolve**: Every week, review "Thumbs Down" queries from production, add them to the Golden Set, and ensure the next model fixes them.
3.  **Regression Testing**: The Golden Set runs automatically via CI/CD on every PR affecting the RAG pipeline.
